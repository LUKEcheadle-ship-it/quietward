# QuietWard v0.6.0-alpha.1

Status: **joint release candidate — paired qualification required before publication**

Python package version: `0.6.0a1`

Companion candidate: QuietWard Response `1.1.0a1`.

## Overview

QuietWard v0.6 connects the observation-only detector to QuietWard Response through a one-way, privacy-preserving local handoff. QuietWard still performs no response action and holds no Response network credential.

The paired workflow is:

```text
QuietWard observation
-> verified QuietWard evidence chain
-> private sanitized local handoff
-> Response-owned authenticated ingestion
-> incident + provenance
-> analyst approval + deterministic policy
-> bounded Response-owned diagnostic
-> signed result + audit
```

## Added

- Sanitized Response-compatible finding handoff contract.
- Installation-keyed HMAC identities for finding subjects and internal finding identities.
- Deterministic Response event IDs derived from keyed finding identity.
- Continuous read-only evidence-chain follower and private local handoff outbox.
- Atomic bounded handoff files, bounded backlog, crash-safe state, and deterministic duplicate handling.
- Exact QuietWard source cycle ID and chain hash on automated handoff events.
- Independent retained-chain hash verification before export.
- Linux systemd user-service installer for the local outbox.
- Focused tests for privacy, provenance, tamper detection, idempotency, state/hash reconciliation, backpressure, and release metadata.

## Privacy and integrity boundary

The handoff does not include:

- raw finding subjects;
- raw internal finding IDs;
- process command lines;
- executable paths from evidence attributes;
- raw file-path subject identity;
- raw source or destination network addresses;
- QuietWard action targets;
- executable proposals or execution authority.

Automated export fails closed if the retained evidence chain does not recompute correctly, if outbox state no longer matches the source chain, if provenance is malformed, if a deterministic handoff file changes, or if the bounded outbox is full.

## Observation-only contract

QuietWard v0.6 still cannot:

- execute Response actions;
- run arbitrary shell/PowerShell/cmd commands;
- terminate processes;
- quarantine or restore files;
- change firewall rules;
- isolate hosts;
- control general services;
- perform autonomous remediation.

`actions_executed` remains zero and executable QuietWard proposals are rejected by the handoff path.

## Qualification

The paired gate is run from the companion QuietWard Response checkout:

```text
python scripts/verify_v11_diagnostics.py --quietward-repo ../quietward
```

Release qualification requires the exact QuietWard and Response candidate SHAs to pass:

- Response backend tests and action-surface lockout;
- fresh and upgrade migrations;
- frontend typecheck, production build, and high-severity dependency audit;
- Response public quick-start smoke;
- QuietWard public-release audit and full test suite;
- QuietWard v0.6 handoff/integrity gate;
- live cross-repository handoff and read-only diagnostic acceptance;
- supported-platform qualification.

## Release packaging

The final release record must name the **exact public release SHA** that passed the paired gate. The deterministic source archive is `quietward-v0.6.0-alpha.1-source.zip` and must be published with its generated **checksum sidecar** and independent archive verification result.

Native **Windows 11** and **Debian 12** qualification must pass on that same candidate pair before publication. Other platforms remain outside the advertised qualified release boundary unless separately tested.

Do not publish or tag this release independently from the paired candidate evidence.
