# QuietWard 0.4.0-alpha.2

This dashboard-focused prerelease turns repeated raw observations into understandable, accessible groups without changing evidence, exports, incident bundles, or CLI review workflows. It also fixes severity priority, first-run guidance, timestamp presentation, reason explanations, and observable refresh behavior.

Corrected pre-rename Debian alpha installations can be upgraded with a private rollback backup while retaining their established privacy and evidence-signing namespaces, signed database, and audited review state.

No remediation capability was added. QuietWard remains local, loopback-only, observation-only, and zero-telemetry. macOS is not supported or natively qualified in this release.

Release is gated on the complete test suite, public-release audit, archive verification, deterministic package comparison, and applicable Windows/Debian qualification evidence.

The release archive is accompanied by a SHA-256 checksum sidecar for independent verification.
The expected archive name is `quietward-v0.4.0-alpha.2-source.zip`.

Native Windows 11 qualification passed for the supported current-user installation and upgrade path. The scheduled task remained current-user and limited, the dashboard remained loopback-only, Windows collection and signed evidence verification passed, and QuietWard executed zero actions. Docker Desktop was absent and produced only the documented optional collector warning.

Final-head validation completed with 160 tests on each qualified platform: 155 passing tests, 0 failures, and 5 expected platform-dependent skips on Windows 11; 160 passing tests, 0 failures, and 0 skips on Debian 12. Native qualification, the public-release audit, deterministic package comparison, and independent archive verification also passed.

The verified source archive contains 142 source files plus its release manifest and is 341400 bytes. Its exact SHA-256 is carried in the adjacent `.sha256` sidecar and the PR #1 qualification record. The digest is intentionally not embedded inside the archive's own source documents because changing those documents would change the digest.
