# QuietWard v0.5.0-alpha.1

Status: **candidate — detection gate and platform qualification required before publication**

Python package version: `0.5.0a1`

Feature scope is frozen for this candidate. Only qualification-driven defect fixes should be added before release.

## Purpose

v0.5 strengthens QuietWard's deterministic detection/correlation layer while preserving its public-product contract: offline-first, privacy-conscious, observation-only, localhost-only by default, and incapable of automatic remediation.

## Detection improvements

### Same-host multi-stage attack chains

QuietWard can now correlate high-confidence events across different subjects on the same host inside a bounded 15-minute window. This allows a sequence such as authentication attack → privilege escalation → persistence → suspicious outbound connection to become one higher-priority finding rather than several unrelated subject-specific findings.

A cross-subject chain requires multiple attack phases and multiple subjects. Background event diversity alone does not qualify. Process/network evidence can also add bounded corroboration when a suspicious process family aligns with adjacent listener/outbound behavior.

### Credential spray

Linux SSH and Windows authentication collectors retain privacy-preserving source/account context sufficient to recognize one source targeting multiple accounts:

- raw source IP is not persisted;
- raw username is not persisted;
- account identities are installation-scoped keyed pseudonyms;
- source addresses use installation-keyed HMAC-SHA256 pseudonyms rather than public deterministic IP hashes;
- the same raw address produces different durable identities under different QuietWard installation keys;
- large multi-account bursts are promoted to HIGH priority when sufficiently corroborated.

Optional outbound destination monitoring uses the same installation-keyed privacy boundary and fails closed rather than persisting destinations when the privacy key is unavailable.

### High-confidence behavioral scoring

Explicit collector markers receive deterministic bounded weighting. High-confidence behavior can receive a HIGH priority floor for markers including:

- reverse shell;
- credential dumping/theft;
- process injection;
- web shell;
- dangerous container configuration;
- Docker socket/host-root exposure;
- document/PDF process spawning a high-risk interpreter or LOLBin;
- web/server process spawning an already suspicious shell chain;
- explicit ransomware recovery inhibition;
- explicit Windows event-log clearing.

The scoring floor affects review priority only. It cannot authorize or execute an action.

### Suppression safety

Ordinary expected/suppressed subject rules remain available for routine noise, but a later event with explicit high-signal behavior bypasses normal subject suppression. This includes malware/YARA/integrity failures and bounded high-signal markers such as reverse shells, credential dumping, credential spray, process injection, ransomware recovery inhibition, dangerous container configuration and event-log clearing.

A lower-specificity marker such as an encoded command alone can still be suppressed. The bypass is deliberately narrow so the feature does not turn every administrative event into an unsuppressible alert.

### Windows parent→child and impact behavior

A document/PDF application spawning a known high-risk interpreter/LOLBin is marked `document_spawned_interpreter`. The detector uses process names and parent PID already present in the read-only inventory. Raw command lines are not persisted.

False-positive regressions cover normal Office child processes and interpreters launched from non-document parents.

The process parser also identifies explicit destructive forms of:

- `vssadmin(.exe) delete shadows`;
- `wmic(.exe) shadowcopy delete`;
- `wbadmin(.exe) delete catalog`;
- `bcdedit(.exe)` recovery disabling;
- `wevtutil(.exe) cl ...` / PowerShell event-log clearing.

Recovery inhibition and explicit event-log clearing are high-confidence review signals. Read/list/query operations do not match. A command that disables Defender real-time monitoring is retained as a lower-weight `defender_tamper_command` context marker rather than receiving a HIGH floor by itself.

The v0.5 release gate also locks the Windows collector/parser contracts for outbound connections, failed-logon evidence and persistence records so those optional/default collectors cannot silently drift away from the PowerShell wire format.

### Linux web/server shell ancestry

A web/server parent such as nginx, Apache/httpd, lighttpd, gunicorn, uWSGI, or php-fpm receives additional correlation only when its shell child already contains a high-signal marker such as a reverse shell, download-and-execute chain, or encoded shell chain. A normal maintenance shell under a web-server process does not receive the ancestry marker by itself.

## Privacy and safety boundary

No new raw command-line storage was introduced for these detections. Windows command lines and sensitive identity-bearing Windows fields use the private installation identity where applicable; Linux arguments remain represented by bounded hashes/markers rather than raw argument text. Authentication source/user and optional outbound-address privacy are protected with installation-keyed identities.

QuietWard does not quarantine/delete files. It also does not terminate processes/services, change firewall rules, isolate a host, install packages during monitoring, upload telemetry, expose a public listener by default, execute arbitrary commands, or perform automatic remediation.

Required invariants remain:

```text
actions_executed == 0
executable_proposals == 0
dashboard_bind == 127.0.0.1
cloud_upload == false
public_listener == false
```

## Qualification

Install the release-test extra from an exact candidate checkout:

```text
python -m pip install -e ".[release]"
```

Then run:

```text
python scripts/verify_v05_detection.py
```

The gate requires the cross-subject chain, process/network corroboration, installation-keyed address privacy, privacy-preserving credential-spray logic, high-signal suppression bypass, corrected Windows collector/parser contracts, Windows and Linux ancestry markers, ransomware recovery-inhibition/log-clearing markers, observation-only invariants, full pytest with warnings treated as errors, compilation, release-document consistency, and the public-release audit.

The candidate must also complete the Windows 11 and Debian 12 platform qualification on the exact release SHA before publication. Deterministic packaging must be built without skipping tests.

Do not publish/tag `v0.5.0-alpha.1` if any detection, privacy, safety, public-release, platform, or packaging qualification check fails.
