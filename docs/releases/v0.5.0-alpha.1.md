# QuietWard v0.5.0-alpha.1

Status: **release candidate — final public-SHA qualification required before publication**

Python package version: `0.5.0a1`

Feature scope is frozen. Only qualification-driven defect fixes are allowed before release.

## Overview

QuietWard v0.5 is the project's largest architecture and detection update. It keeps the public contract unchanged: offline-first, observation-only, privacy-conscious, read-only dashboard, and no automatic remediation.

This release combines the approved lower-overhead performance/lifecycle core with the public v0.5 detection/privacy hardening work.

## Major improvements

### Lower-cost always-on monitoring

QuietWard separates monitoring into explicit cadence lanes:

- **FAST** — processes, listening sockets, optional outbound connections and authentication;
- **STANDARD** — persistence and Docker state;
- **DEEP** — sensitive files and self-integrity;
- **MAINTENANCE** — heavy local scanners and bounded housekeeping.

Heavy work is staggered. A bounded adaptive governor may briefly defer only DEEP/MAINTENANCE work when the measured fast profile is under pressure. FAST and STANDARD are never governor-deferred, and incident-relevant work overrides deferral.

Quiet healthy cycles reduce redundant database/snapshot writes inside a bounded durability window. Security-bearing or degraded observations remain immediately durable.

### Faster Windows collection

Quiet Windows FAST cycles use read-only native Windows APIs for fresh process/PID and listening-socket inventory, avoiding PowerShell startup on the normal quiet path. The fixed read-only PowerShell collector remains a fail-closed fallback and can provide deeper process detail when newly risky evidence requires it.

Defender status, richer account context and persistence enumeration are refreshed on the slower STANDARD/cold path. Windows command execution resolves trusted absolute executables from OS-derived roots, rejects links/reparse paths, uses fixed allowlisted commands, runs with `shell=False`, and uses a sanitized environment.

### Incident lifecycle and reduced alert noise

Findings now have stable `new`, `recurring`, `changed`, and `resolved` states. Lifecycle resolution is source-aware, so an incident cannot resolve merely because an unrelated cadence did not observe its source domain. Unchanged recurrence does not continuously re-alert; material escalation and true reappearance can alert again.

### Cross-signal and multi-cycle context

QuietWard correlates corroborating signals from the same actor and retains a bounded five-minute in-memory context window across successful cycles. The temporal window is bounded, does not create a second durable history store, and is discarded on failed cycles. Cross-cycle PID matching is guarded against PID reuse, and generic runtimes are excluded from unsafe name-only actor matching.

### Detection improvements

Deterministic scoring adds bounded explicit weighting for high-confidence behaviors including:

- reverse-shell behavior;
- credential dumping/theft;
- credential spray;
- process injection markers;
- document/PDF application spawning a risky interpreter/LOLBin;
- Linux web/server parent spawning an already-suspicious shell chain;
- ransomware recovery inhibition;
- Windows event-log clearing;
- dangerous container configuration, Docker socket and host-root exposure;
- same-host multi-stage attack chains and process/network corroboration.

These signals change review priority only. They cannot authorize or execute an action.

### Credential-spray and address privacy

Linux SSH and Windows failed-logon evidence recognize one source targeting multiple pseudonymous accounts without persisting raw usernames or source IP addresses. Authentication source addresses and optional outbound destinations use installation-keyed HMAC-SHA256 pseudonyms and fail closed if the required privacy identity is unavailable.

### Suppression safety

Expected/suppressed rules are scoped to the event kinds actually reviewed. If the exact signed source cycle for a contextual finding cannot be recovered, QuietWard keeps the review state but creates no suppression rule. Explicit high-signal behavior bypasses ordinary suppression.

### Evidence, restart, and retention efficiency

Evidence verification is incremental between mandatory full retained-chain audits. New durable rows or external SQLite changes invalidate the cache; an incremental mismatch falls back to the authoritative full verifier.

A warm restart is allowed only from recent, established, healthy and cryptographically verified state. FAST observation resumes immediately while heavier revalidation is staged. Missing, stale, degraded or invalid state falls back to the full cold-start path.

### Dashboard and supportability

The read-only local dashboard exposes active incident lifecycle, monitoring coverage, evidence integrity, retention pressure, current findings/review state, Defender/collector context, and explicit zero-action safety state. Runtime health records per-cadence timing, external command count/time, QuietWard CPU/RSS, persistence mode and health-write mode.

### Redacted incident export v2

Incident exports hash host identifiers and signing-key identity in addition to subjects, exclude analyst notes/proposal reasons, and include only allowlisted lifecycle/coverage context.

## Safety boundary

QuietWard remains observation-only. It does not automatically:

- quarantine or delete files;
- terminate processes or services;
- change firewall rules;
- isolate the host;
- execute arbitrary shell/PowerShell/cmd commands;
- install packages or update scanner signatures during monitoring;
- upload telemetry to a cloud service;
- authorize remediation from the local model or dashboard.

Required invariants:

```text
actions_executed == 0
executable_proposals == 0
cloud_upload == false
public_listener == false
```

The dashboard remains read-only and loopback-only by default. Explicit private-network binding still requires the private-bind/token controls.

## Release tooling contract

The release tree must pass the public-release audit, complete repository tests, Python compilation, static observation-only safety audit, deterministic double release-bundle build, checksum sidecar generation, and independent archive verification.

The release builder freezes the current-head commit before validation and verifies that the same commit is still checked out afterward. It refuses to overwrite an existing archive or checksum sidecar and independently recomputes the final archive SHA-256.

Native Windows 11 and Debian 12 qualification remain required on the exact public release SHA before tag/publication.

## Positioning

QuietWard v0.5 remains an **experimental alpha**. It is not a replacement for Microsoft Defender, enterprise EDR/MDR or professional incident response, and it should not be marketed as preventing every breach or producing zero false positives.
