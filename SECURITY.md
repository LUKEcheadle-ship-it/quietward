# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability, bypass, privacy leak, or exploit path.

Use GitHub's private vulnerability reporting feature when it is enabled for this repository. Until then, contact the maintainer privately through the contact method listed on the maintainer's GitHub profile and include `QuietWard security report` in the subject.

Include the affected version or commit, a minimal reproduction, expected and actual behavior, potential impact, and whether the report contains sensitive host information. Do not attach malware, credentials, private logs, scanner databases, or real host inventories.

## Scope

Security reports may cover command-boundary bypasses, unsafe scanner execution, dashboard exposure, secret or raw-address persistence, suppression of authoritative findings, executable action paths, evidence-chain failures, installer/uninstaller problems, and denial-of-service conditions.

QuietWard is observation-only. It is not an antivirus replacement, not a guaranteed intrusion-detection system, and not professional incident-response advice.

## Disclosure

Please allow reasonable time for validation and remediation before public disclosure. The maintainer will acknowledge credible reports, coordinate fixes, and credit reporters who request attribution.
